# Bootstrap the pinned release

1. Run this skill's `scripts/bootstrap.py` with Python 3. It verifies the installed release selected by `--state`, `PROFESSIONAL_REPORTS_STATE` or `~/.local/share/professional-reports`. Retain the returned root, version and hash throughout the run. Do not substitute a checkout or silently reload latest; report a missing installation.
2. From that root, inspect `python3 -m pr --help` and the relevant command help/schemas. Use `load` and exact `{id, version, sha256}` component references. Register `run` before substantive meta selection/planning, preserve the actual `requested_at`, and start the supported `pr.budget` watcher immediately. Report work has a 600-second ceiling and default 585-second work cutoff; 300 seconds is aspirational only. Full-report experiments also enable `report_benchmark.enabled=true`. Read `docs/report-speed.md` for timing and experiment gates.
3. Load the resolved `meta-orchestrator` and `codex-native` entrypoints. Use `meta` and `plan` for the mandate-specific graph; snapshot actual sources and approved-design inputs before dispatch. Bind only necessary skills, retaining all their required checks, consumes and outputs. Non-valuation domains stop at planning in this release.
4. Read `docs/session-workflow.md` for task-scoped sessions and the runtime's versioned `session-policy.json`; read `docs/native-handoff.md` when binding/submitting host work. `dispatch` prepares work; actually spawn each worker with `fork_context=false`, inherit the user's model and `bind` its real receipt. Obey the lower confirmed host limit, never exceeding six live workers. Unknown settings/capacity stay unknown.
5. Wait for actual output and `submit` actual files/checks. Each review round uses a fresh independent native reviewer bound to current hashes, criteria and relevant evidence; submit its result before recording `review`. Retain per-finding resolution or reopening evidence and scoped accepted decisions. Preserve results and actually close each worker with a close receipt. Completed workers never resume for new tasks.
6. Inspect `status`, route revisions through fresh attempts and `export` permitted deliverables. Reuse approved design only by actual hash; render and inspect all pages of the first document, then justified changed/affected pages. Keep protected acceptance criteria unchanged. Independent quality evaluation and supported `finish` gates remain required; ordinary review/export do not establish completion. At the budget watcher's delivery action, actually cancel returned host IDs, preserve available work and deliver its complete/incomplete disposition.

Load persona and method references only for assigned work. Missing operations, tools, telemetry or checks remain explicit limitations. Installed schemas govern request spellings; this bootstrap does not implement the engine or certify financial correctness. Use `docs/performance-profiler.md` only for measured performance diagnosis.

For assigned risk work, read `docs/risk-workflow.md` from the pinned release if available; resolve only selected risk methods/persona. PM and runtime must bind actual risk objects, profile version/hash, adoption evidence and cost to plan node IDs/revisions through supported records. Missing installed methods remain missing. Risk records do not grant permission. Package implementation approval and task/profile adoption are distinct; candidates stay shadow until concrete adoption. Preserve protected criteria and invalidate affected confidence/reviews on reruns or consumed-input changes. Numeric 1%/0.5% values are not installed defaults. These development definitions add no generic FDD/ESG execution support or production approval.
