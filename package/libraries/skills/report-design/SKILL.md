# Reuse the existing presentation reference

Read [method contract](contract.json), [execution boundary](references/execution-contract.md)
and [existing design reference](references/approved-design.json). The reference
preserves a historical presentation selection by artifact hash. It is not a new
review or a reusable financial approval. Paths are repository-relative lookup
hints; consumers must resolve and verify the exact bytes before using them.
Missing external reference files yield an unresolved reference, not an automatic
substitution or an absolute path back to the author's machine.

## Define the handoff

Keep the user's language, output format, analytical structure, content and selected
profile. The recorded native profiles are transaction, executive and editorial;
the referenced presentation selected transaction. Reuse that design when suitable
for the mandate; no repeat A/B/C competition is required for a content update.
Changes to requested design or acceptance criteria must be recorded and handled
under the mandate's change authority, not silently imposed by this skill.

Freeze the current content packet: section/paragraph IDs, argument and claim
bindings, tables/cells/notes, metric/result paths, scenarios, units, dates, citations,
limitations and actual source/model/substantive-review coverage. Rendering does
not select methods, tune assumptions, improve results or grant review acceptance.
If current content has substantive weaknesses, return it to the author before a
presentation-only revision; cosmetic constraints cannot freeze incorrect content.

Map every supplied section and exhibit to the intended pages/blocks. Select
visual hierarchy for the reader's decision, with finding-led titles, visible
units/source notes, legible body/table/caption text and repeat headers for long
tables. Chart geometry comes from bound current values; never copy a historic
chart as current evidence. Preserve adverse findings and qualifications near the
claim. Avoid arbitrary page counts or shrinking text to force a specimen length.

## Implementation boundary and verification

The package includes neutral report-outfit transaction/executive/editorial constructors,
CSS and licensed fonts under `adapters/valuation/vendor/`; their exact files are
pinned in the release manifest. `adapters/valuation/build.py --input <current.json>
--out <fresh-directory> --design <profile> --recalc required --pdf required` builds
valuation HTML/PDF/XLSX from the common graph and supplied bound narrative.
Resolve paths from the loaded release root, not a development checkout. Read the
adapter README and input schema first. Native PDF rendering and spreadsheet
recalculation require successful runtime probes and observed execution on this
host. Included code is not proof of a successful run or a professional result.
The inherited presentation reference remains historical. Neutralized branding,
new content and generated artifacts require their own recorded visual review.
FDD, ESG and board execution are not supplied by the valuation adapter.
If that runtime is supplied, use explicit current inputs and fresh outputs; reject
sample fallback. Reconcile content retention and numeric/display bindings, inspect
all actual PDF pages for clipping, missing glyphs, truncated tables, charts, notes,
links and pagination, and bind results to the exact final bytes. HTML appearance
alone cannot verify a print PDF. Independent review, when required, must use an
actual host-provided reviewer; record author inspection honestly otherwise.

Return a design-reference binding, mapping/handoff specification, acceptance
checklist and unresolved capability record. With a verified external renderer,
also record actual artifact bindings and executed checks. Do not claim a new
report was generated by completing the handoff. Prior firm branding or wordmarks
do not confer authorship, endorsement or permission to distribute new branded
reports; no external firm wordmarks or historical company report data are vendored.
