# Execution boundary

These are local provisional agent methods, not runtime enforcement. Resolve assigned components through the pinned registry as exact `{id, version, sha256}` references. No nested spawning: the host dispatches native workers with `fork_context=false`, inherited model, actual spawn/bind/submit/close receipts and the lower confirmed live-worker limit (never above six). Requested, resolved and observed settings remain separate; unavailable observations stay null with a reason. A fresh independent reviewer is required each round; independence follows actual producer lineage, not a persona label.

Bind inputs by ID, relative location, version, measured hash or access limitation and consumed fields. The riskfile is an evidence artifact, not execution permission, package approval or profile adoption. The host maps risk objects, profile and cost to actual plan tasks; these definitions do not add scheduler logic. A changed consumed input, source, model, criterion, profile, control, artifact, task scope or real counterevidence invalidates affected outputs, confidence and downstream reviews. Reruns create new attempts; a fresh date or repeated result cannot restore confidence. Revalidate affected bindings and controls, then obtain fresh independent review of changed/affected artifacts. Only evidenced unchanged scope can retain scoped accepted decisions.

Every output has an ID, relative location/version, bindings and actual checks. `operation_record` carries actor/attempt, observed execution, status (`complete`, `restricted`, `returned`), limitations and affected descendants. Each `failure_records` entry names the record, missing evidence/test, consequence, owner, next action and interim restriction. Apply current protected criteria unchanged; missing prerequisites return restricted/unverified outcomes. Package implementation approval is distinct from adoption of a concrete profile and per-task settings. A proposed profile is shadow until its version/hash, scope and actual user adoption record are bound. Proposed 1% and 0.5% values are not installed defaults or assurance guarantees. Main coordination supplies the standards sourcepack; no standard is inferred here.
